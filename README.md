# CourseMind

**AI Study Assistant for Your Course Material**

Upload your own course material (PDF) and get **answers** and **full-document summaries** grounded in that specific document — with the source (file + page) cited, and an explicit "not found" instead of a guessed answer when the material doesn't cover a question.

> **Status: Phase 10 complete — MVP finished.** PDF upload, indexing, grounded Q&A with source citations, full-document study summaries, and a real evaluation suite are all implemented and verified end-to-end.

## The problem

University and college students, across different academic fields, struggle to quickly find accurate answers inside their own course materials (PDFs, lecture slides) before an exam.

## Target audience

University and college students **in general**, across different academic fields (not limited to technical fields), who study from course materials such as PDFs, lecture slides, notes, and other learning documents — preparing for an exam.

## Current MVP features

- **Upload a PDF** course document through the Streamlit interface.
- **Process/index it** on demand — text extraction, chunking, OpenAI embeddings, and storage in a local Chroma vector store. Re-processing the same document never creates duplicate records.
- **Automatic scan on upload** — as soon as a document finishes processing, the app tells you what is inside it (main topics, in the document's own order), without you having to ask.
- **Ask questions** about the uploaded material in Hebrew or English. Answers are generated by a real CrewAI agent that decides when to search the material (a Tool), and are **strictly grounded**: if nothing relevant is found, the app returns a fixed "not found in the uploaded material" message instead of guessing.
- **Understands the question before searching.** Wording no longer decides whether you get an answer: "מה התוכן של הקובץ?", "מה התוכן שיש בקובץ שהעלינו?", "מה למדנו בקובץ?" and "תן לי סקירה של המסמך" all reach the same document overview. A small classifier (`services/query_understanding.py`) reads the question, decides *how* to search it, and proposes alternative search wordings; deterministic guards then check that decision.
- **Four question types, routed by Query Understanding** (the model proposes, guarded code disposes — and the model never decides whether an answer exists):

  | You ask | Mode | How it is answered |
  |---|---|---|
  | "What is an Array?" | `semantic` | RAG similarity search over the active document, seeded with alternative search wordings |
  | "What is on page 5?" | `page` | Structural lookup by stored `page_number` — answered from that page only, or a clear "that page does not exist" |
  | "What is in this file?" / "Which topics does it cover?" | `overview` | Whole-document coverage (every page), not top-k |
  | "How many pages does it have?" / "What is the file called?" | `metadata` | Straight from the index's own bookkeeping — exact counts, no LLM, no sources cited (that fact is not written on any page) |

- **See real source references** (file name + page number) for every grounded answer — never citations invented by the model.
- **Generate a full-document study summary** — a separate workflow that processes the *entire* document (not just the most relevant snippets) via hierarchical map-reduce summarization, structured for exam study (main topics, key concepts, definitions, rules, examples, terminology, takeaways).
- Clean loading/success/warning/error states throughout, and correct rendering of mixed Hebrew/English (RTL/LTR) content, including code blocks.

### How a question is routed

```
question
   │
   ├─ Stage 0  fast path, no API call
   │            explicit page number  -> page
   │            "how many pages" / "what is the file called" -> metadata
   │
   ├─ Stage 1  classifier (gpt-4o-mini, temperature 0, JSON)
   │            returns intent + 2-3 alternative search wordings
   │            it is NEVER given document_id, and has no "unrelated" label
   │
   ├─ Stage 2  deterministic guards
   │            an overview must actually refer to the document
   │            injection wording ("ignore the pdf", "תשכח מההוראות") forces semantic
   │            a page route needs a real page number in the text
   │            anything else -> semantic, the fail-safe route
   │
   └─ retrieval -> grounding gate -> answer or "המידע לא נמצא בחומר הלימוד שהועלה."
```

Two properties are deliberate, and both came out of measurement:

- **The classifier cannot say "not found".** Given an `unrelated` label it classified
  *"מה זה משתנה ב-JavaScript?"* — a perfectly answerable question — as unrelated,
  because it cannot know what the document contains. Whether an answer exists is
  decided only by retrieval and the programmatic grounding gate, which have evidence.
- **The classifier cannot reach another document.** `document_id` is never passed to
  it. A rewritten query changes which chunks of the *same* document come back, never
  which document is searched.

If the classifier is unreachable, routing falls back to the regex rules — a classifier
outage can never fail a question.

## High-level architecture

```
PDF upload (Streamlit)
   │
   ▼
Ingestion Pipeline (automatic, not agent-controlled)
   text extraction → chunking (+ file/page metadata) → embeddings → vector store
   │
   ▼
Vector Store (Chroma)
   │
   ├──► Q&A: services.answer_question()
   │      → CrewAI Agent → RAG Retrieval Tool (top-k) → grounded answer + sources
   │
   └──► Summary: services.summarize_document()
          → ALL document chunks (not top-k) → map/reduce → full-document summary
```

The **Ingestion Pipeline** is deliberately separate from the **Agent Tools**: ingestion runs automatically when you click "Process document" and is not something the agent decides to invoke, while the RAG Retrieval Tool is a capability the agent itself chooses to call while answering a question. The Summary workflow is a separate, non-agent pipeline (by design — a full-document summary must not rely on top-k retrieval).

## Security

The OpenAI API key is **never** hardcoded anywhere in the source, printed, or shown in the UI. It is read from a local `.env` file, and `.env` is excluded from version control via `.gitignore`.

## Setup

### Quick setup (Windows)

```powershell
git clone https://github.com/abohaab-cell/CourseMind.git
cd CourseMind
.\setup.ps1
```

`setup.ps1` finds Python 3.12 explicitly, builds the virtual environment, installs the dependencies, and checks that every required package actually imports. Then add your OpenAI API key to `.env` and run `.\venv\Scripts\python.exe -m streamlit run app.py`.

The manual steps below do the same thing by hand.

### 1. Create and activate a virtual environment (Windows)

**Use Python 3.12 explicitly.** Do not rely on whatever `python` resolves to on your PATH:

```powershell
py -3.12 -m venv venv
.\venv\Scripts\activate
```

Two things go wrong otherwise, and both have actually happened:

- **A different Python version.** Python 3.13/3.14 (and especially the free-threaded `python3.14t.exe`) has no prebuilt wheels for `chromadb`, `tiktoken` and `pydantic-core`, so the install fails part-way and leaves a broken environment where `streamlit` exists but `pypdf` does not.
- **A non-Windows Python.** An MSYS2/mingw `python.exe` creates a Unix-layout venv with `bin/` instead of `Scripts/`, so `venv\Scripts\pip` simply does not exist.

Check what you got before continuing — it must say 3.12.x:

```powershell
.\venv\Scripts\python.exe --version
```

Also note the leading `.\` in PowerShell: without it, PowerShell treats `venv\Scripts\pip` as a command name and reports `The module 'venv' could not be loaded`.

### 2. Install dependencies

```bash
pip install -r requirements.txt
```

### 3. Configure environment variables

Copy `.env.example` to `.env` and fill in your own values (no real secrets are committed to this repo):

```
OPENAI_API_KEY=
OPENAI_MODEL=gpt-4o-mini
OPENAI_EMBEDDING_MODEL=text-embedding-3-small
```

`OPENAI_API_KEY` is required; the model variables have sensible defaults if omitted.

### 4. Run the app

```bash
streamlit run app.py
```

Then, in the app: upload a PDF, click **Process document**, and once it's indexed you can ask questions or generate a full study summary.

## Evaluation

A real, scripted evaluation suite exercises the live backend (real CrewAI Agent, real RAG Tool, real ChromaDB, real OpenAI API) — not fake stand-ins.

**What is evaluated:** retrieval quality, grounding behavior, source correctness, document isolation, Q&A behavior (factual/explanation/multi-chunk), full-document summary coverage (including a known *late-page* topic, not just the first few pages), Hebrew and English question handling, and failure safety (a simulated internal retrieval failure must raise a distinguishable technical error, never a fabricated answer).

**Cases:** 13 cases across 9 categories (`factual`, `explanation`, `multi_chunk`, `source_tracking`, `no_evidence`, `document_isolation_negative/positive`, `english`, `summary_coverage`/`late_page_coverage`, `failure_safety`), defined in `evals/test_cases.json`. Ground-truth expectations (source pages, page/chunk counts) were determined by directly inspecting the reference PDF's real indexed content *before* running the eval, not adjusted after seeing results.

**How to run:**
```bash
python -m evals.run_evals --pdf "path\to\JavaScript_חלק_א_מדריך_לימוד.pdf"
```
The reference PDF isn't committed to the repository (it's a personal file used during development) — supply your own copy via `--pdf`, or any PDF, though content-specific checks (keywords, page numbers) are calibrated to that specific file and will legitimately not match a different document. A small secondary document (for isolation/English checks) is built as a synthetic in-memory fixture, so it never depends on a private file.

**Results are saved to:** `evals/results/latest_results.json` (machine-readable) and `evals/results/latest_report.md` (human-readable).

**Last real run:** 13/13 passed (100%). Source hit rate 5/5, grounding refusal 2/2, document isolation 2/2, summary coverage 4/4 plus late-page topic PASS. See `evals/results/latest_report.md` for the current numbers — this README does not duplicate them so it can't go stale.
